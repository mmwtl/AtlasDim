## Реализация

Предпросмотр 1920×532 и кадры используют один `SceneRenderer`. Цвет фона,
непрозрачность 0…255, сетка 100 px, секунды и подложка часов настраиваются.
Оба слоя имеют отдельные enable/display/z/x/y/w/h. Настройки сохраняются
при «Показать / применить». «Убрать всё» доступно вне прокручиваемой формы.

QNX: два экземпляра имеющегося бинарника, clock TCP 49210 и background
TCP 49211; исходный бинарник не изменён. Общая сессия останавливает прежние
процессы один раз, запускает оба и закрывает всю композицию при ошибке одного
соединения. Каждый канал поддерживает heartbeat независимо, в том числе
пока второе окно ещё подключается. Фон передаётся один раз, часы — при
изменении текста. Уход с Activity закрывает оба сокета.

На dpy-1 разрешены часы z<10 и фон z<3. Нельзя задать одинаковый z двум
окнам на одном display; геометрия проверяется без переполнения int. Если
ввести ошибочные настройки, текущая отправка продолжается, новый вариант
не применяется, предпросмотр помечает последний корректный вариант.

## Ограничения и следующий живой тест

- Имитатор не исполняет QNX-бинарник: совместимость двух процессов со Screen,
  копирование/запуск по telnet, реальный z и цвета/alpha требуют проверки на ГУ.
- Предпросмотр содержит только наши окна. Прозрачность штатного `cluster-hmi`
  неизвестна: фон dpy-2 может быть закрыт его непрозрачными областями.
- Выход из Activity проверен. Краш Android и потеря сети должны убрать окна
  через EOF/watchdog демона, но это ещё не подтверждено на QNX. После краша
  процессы могут оставаться без окон до следующего запуска/перезагрузки.
- Без пароля display/z берутся из вручную запущенных демонов. UI не может
  изменить или проверить их через gcp/1; пользователь должен согласовать настройки.
- С паролем демоны останавливаются после закрытия соединений; если telnet
  недоступен, приложение сообщает, что остановка не подтверждена. `/tmp`
  остаётся до перезагрузки, системные процессы не скрываются и не изменяются.
- Центральный экран: ограниченная тестовая область 1440×532, не полноэкранные
  1440×1920, из-за лимита высоты текущего бинарника.

На стоянке: сначала часы dpy-1 z=5, затем добавить фон dpy-2 z=1;
проверить лампы и штатные приборы, координаты, прозрачность и сетку;
«Убрать всё», повторное применение, выход, принудительное закрытие приложения
и обрыв соединения. После каждого шага подтвердить возврат штатной картинки
и состояние только наших процессов через `pidin ar`.

## Демоны без остановки при обрыве (ветка diagnostics, 2026-10-14)

- Причина: каждая ошибка gcp/1 вела к остановке демонов по telnet и повторному
  запуску по telnet — при нестабильной связи с QNX обрыв усиливался.
- Теперь окно при закрытии получает прозрачный кадр, затем `shutdownOutput` и
  закрытие; запись ограничена 2 с, чтобы не зависнуть на мёртвой связи.
  Демоны останавливает только «Убрать всё» или смена хоста/пароля.
- После успешного запуска по telnet в prefs (`daemons`) запоминаются хост, версия
  APK и display/z окон. Совпадает — окна открываются без telnet; демон не
  отвечает — сразу (без 10-секундного повтора) telnet и `prepare`.
- Таймаут чтения ответов демона после HELLO — 15 с вместо 5 с.
- Эмулятор `emulator-5554`, `SceneTestRunner`: 14/14, новые проверки —
  прозрачный кадр перед закрытием; запомненные демоны без telnet при старте и
  остановке; отсутствующий демон — переход к telnet быстрее 4 с. Lint без новых
  предупреждений.
- Не проверено на ГУ: что демон убирает окно после прозрачного кадра и закрытия
  (проверять на стоянке), и повтор после перезагрузки QNX с запомненными демонами.
- Переключатель «Запускать демоны автоматически» убран: `/tmp` на QNX чистится при
  загрузке, без telnet демонов нет. Пароль берётся из поля или сборки; без него
  «Показать / применить» отказывает («Введите пароль root QNX»). UI-тест подключается
  к имитаторам через запомненные демоны (telnet на 127.0.0.1 недоступен) — 14/14.
