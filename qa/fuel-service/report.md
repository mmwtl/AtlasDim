## Изменения

1. Возвращены ограничения слоёв (отмена v0.13.0-test-layers): на dpy-1 фон z<3,
   остальные окна z<10 (лампы); окна на одном дисплее — с разными z. Подсказки UI
   вернулись к прежним.
2. Новое окно «Топливо» — третий демон `ghudbridgelited-dim-fuel<N>`, TCP 49212.
   Залито и свободно в литрах (каждое можно отключить), своя подложка.
   Датчик Fuel Percentage (id 4211968) из GInputBridge: LISTEN/GET каждые 30 с,
   ответы — неявные broadcast. Формула и контракт скопированы из AtlasClimateWidget
   (`Fuel.java`, `Gib.java`): литры = значение × 0.5 + 4, бак 54 л, на нуле `<4`/`>50`;
   множитель и смещение можно поменять. Без ответа 5 минут — «—». Кадр уходит
   только при смене текста, иначе PING. По умолчанию окно выключено (место на ГУ
   не проверено): dpy-1 z=8, 300×50 @1620,482.
3. Работа в фоне: композицию держит foreground-сервис `SceneService` (уведомление
   IMPORTANCE_MIN). Применённая конфигурация хранится в prefs JSON (`scene`, `active`);
   уход с Activity окна больше не закрывает. Обрыв или отказ — повтор 5/10/20/40/60 с.
   «Убрать всё» останавливает сессию и демоны, затем сервис.
4. Автозапуск: `BootReceiver` (BOOT_COMPLETED, QUICKBOOT_POWERON, MY_PACKAGE_REPLACED)
   поднимает сервис, если композиция активна; после загрузки — только при включённом
   «Возвращать на приборку после загрузки ГУ» (вкладка «Связь», по умолчанию вкл.).

2. `am instrument -w com.mmwtl.atlasdim.test/com.mmwtl.atlasdim.SceneTestRunner`:

   с настоящим ГИБ в тесте приёмника — стабильно.

## Ограничения

- Место окна топлива на приборке не проверено — по умолчанию оно выключено.
- На машине нужен установленный GInputBridge; без него топливо показывает «—».
- Холодный старт ГУ: QNX и telnet могут подниматься дольше Android — это покрывают
  повторы сервиса; живая проверка на ГУ нужна.
- После `am force-stop` Android не присылает BOOT_COMPLETED, пока приложение не открыть.
- Окна по-прежнему не выше приборов (фон) и не выше ламп (все окна) на dpy-1.
