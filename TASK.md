# AtlasDim — план: фон и часы на приборке

Цель: рисовать свои **часы** поверх приборки ГУ G636 и отдельный **фон** под
штатными приборами. Навигация/медиа в штатные слоты уже решены в других проектах
(медиавиджет) — здесь не занимаемся.

Факты — `notes/RESEARCH.md`, команды — `notes/commands.md`.

## Почему только через QNX

- Приборка — QNX Kanzi (`cluster-hmi`) на QNX Screen dpy-1 поверх фона dpy-2.
  Android-окна туда не попадают (Android-дисплеи 1/3/4 — живой тест, пусто).
- Штатный канал (binder → fdbus) даёт только штатные слоты, произвольного текста
  или картинки там нет.
- Остаётся свой процесс на QNX с окном QNX Screen на dpy-1 поверх `cluster-hmi`
  (order 3) и под контрольными лампами `EarlyTT` (order 10).

## Решение

- **QNX**: `ghudbridgelited` из ANHUD (открытый, 30 КБ, QNX 7 aarch64): окно
  QNX Screen с прозрачностью (`transparency` 3 = source-over), `--z -100..100`,
  принимает RGBA-кадры по TCP (протокол gcp/1). Патч: дисплей `4 → 1`, лимиты
  окна `800×480 → 1920×532` (смещения — RESEARCH.md п. 5, перед патчем сверить
  дизассемблером). Запуск из `/tmp` с `--z 5`. Штатный UI приборки не трогаем
  и не скрываем — часы ложатся небольшим прозрачным окном в свободное место.
- **Android**: Bitmap с часами (Canvas, без VirtualDisplay) → gcp/1 HELLO
  (размер и позиция окна) → FRAME раз в секунду/минуту. Клиент протокола — по
  образцу `hudbridge/` из ANHUD (Gcp.kt, HudLink.kt) на Java.
- **Композиция v0.8.0**: два экземпляра того же демона — фон (TCP 49211,
  по умолчанию dpy-2 z=1, 1920×532) и часы (TCP 49210, dpy-1 z=5).
  Отдельные display/z/геометрия/включение, цвет и непрозрачность фона,
  тестовая сетка. Общий Canvas-рендерер для предпросмотра и кадров.
- **Возврат**: окно живёт, пока жив демон и есть связь; демон сам убирает окно
  при потере связи. Приложение останавливает только свои процессы из `/tmp`;
  имена и команды — `notes/commands.md`. `/tmp` на QNX
  очищается при перезагрузке — после ребута ничего нашего не остаётся.

## Сессия 1 на ГУ — только чтение (≈10 мин)

1. Место для часов — левый нижний угол (решение пользователя); по фото уточнить
   координаты (по умолчанию окно 300×100 в точке 40,412).
2. QNX (только чтение): версия (`uname -a`), есть ли `libscreen.so.1`,
   права/исполнение в `/tmp`, видна ли NFS-шара `/shared`, состояние окон
   dpy-1/dpy-2, нет ли в ресурсах приборки скрытых часов
   (`grep -ril clock /apps/cluster`).
3. Android: доступность QNX по TCP из приложения (порт будет проверен в сессии 2).

## Подготовка (без машины) — сделано: `qnx/ghudbridgelited-dim`, `qnx/qnx.sh`, APK v0.8.0

- Сверить смещения патча дизассемблером, собрать `ghudbridgelited-dim`
  (дисплей 1, лимиты 1920×532), проверить `--version`/`--help` строки.
- Тестовое приложение: клиент gcp/1 + рисование часов + кнопки
  «подключить / показать / убрать», поле позиции/размера, лог `AtlasDim`.

Ограничения редактора: на dpy-1 фон z<3, часы и топливо z<10 (лампы); у окон
на одном дисплее z различаются. Тестовая версия v0.13.0-test-layers снимала эти
ограничения; с v0.14.0 они возвращены — выше приборов и ламп не выводим.
z сравнивается внутри дисплея, dpy-1 расположен поверх dpy-2. Для теста на центральном dpy-3
отрисовывается отдельный предпросмотр, окно ограничено областью 1440×532
(лимит высоты текущего демона). Полноэкранное окно 1440×1920 не поддерживается.

## Сессия 2 на ГУ — запуск своего процесса на QNX (нужно согласие)

Стоянка. Копия демона через `/data/vendor/nfs/shared` → `/tmp`, `chmod 755`,
запуск `--z 5`. Из приложения — HELLO и кадр с часами в выбранном месте.
Проверяем: часы видны, прозрачность, не перекрыты ли лампы и стрелки,
задержка. Затем выход из приложения → окно пропало, `slay` демона → приборка
без изменений. Отчёт — `qa/clock/report.md`.
